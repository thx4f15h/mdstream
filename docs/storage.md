# 存储、查询 scratch 与缓存回收测量

本实验在核心性能矩阵之外，量化语义节点、查询栈和检查点生命周期。工作负载和测量由 `crates/mdstream-core/tests/support/storage.rs` 共享给 `crates/mdstream-core/examples/storage.rs` 与 `crates/mdstream-core/tests/storage.rs`，无依赖和 unsafe。时间只作观测，验收基于容量、计数和独立模型。

仓库现采用 workspace 布局；本文正文使用当前路径，已保存的 `*-environment.txt` 与基线 CSV 是测量时生成的原始快照，内部仍保留当时的 `src/`、`tests/`、`examples/` 路径。

## 复跑与原始记录

```bash

# 可选参数：基准字节参数、窗口查询次数、独立进程次数

# 子索引涉及字长，另在实际 i686 二进制中验收
nix develop .#index32 -c cargo nextest run --workspace --target i686-unknown-linux-gnu --test storage
```

脚本拒绝已有目录和非法参数，保存环境、Git HEAD/脏状态、源码 SHA-256、Cargo metadata 的权威 target 目录、每轮 CSV 和日志，并逐项核对各轮非时间字段相同。每进程运行 base、4 × base、16 × base 三规模，默认 4,096 / 16,384 / 65,536。初次压缩实验每规模 27 个阶段，共 81 个阶段、732 条指标（包括各阶段耗时）；新增查询复用对照后，查询复用版每规模 42 个阶段，共 126 个阶段、1,101 条指标；加入下方历史树压缩实验后，当前驱动每规模 54 个阶段，共 162 个阶段、1,521 条指标。CSV 是长表 `schema,case,scale,phase,metric,value`，schema 为 1；scale 在解析/视口场景是生成参数，在检查点场景是状态数，不等于所有场景的实际源码长度。

[原始对照 CSV](storage-baseline.csv) 保存压缩前一轮与压缩后三轮，增加 `variant,run` 两列，共 2,928 条指标。[环境记录](storage-environment.txt) 保存后三轮执行时的工具链、主机及源码摘要。环境为 ark、AMD Ryzen 7 255、Linux 6.18.54、x86_64、Rust/Cargo 1.99.1，release 默认配置；后三轮开始于 2026-10-30 15:07:18 UTC，基于 `47bc3f3a2d69f70da1750986436ce04457db9f67` 加本单元工作树。前一轮使用相同测量代码及未压缩的该提交 `crates/mdstream-core/src/checkpoints.rs`。前三类解析输入额外记录实际字节数及 FNV-1a 指纹。没有固定 CPU 频率、绑核或清空缓存。

## 口径与场景

- **解析**：纯文本、密集行内标记、重复引用/列表三种 ASCII 输入，4 KiB append、复用 Update，最终 finish。记录 annotation/container arena 容量、增长分配调用及解析访问数。时间不含输入生成、初始 Document 创建和结果格式化。`annotation_node_bytes` 来自当前实现初始单节点、单槽 Vec 的实际容量字节数。
- **语义查询**：在中部八个相邻起点查询 256 字节窗口，每次新建 Runs；另执行一次全篇查询，仅用于测量遍历栈峰值，不是建议的渲染策略。`Runs::scratch_stats()` 返回待处理栈帧数、实际容量字节和本迭代器累计分配/扩容调用。栈只增长，结束时容量就是该栈峰值；新迭代器重新分配。查询时间含借用片段遍历、指纹校验和 `black_box`，不等于裸索引或真实终端绘制耗时。初次实验未覆盖 DisplayCursor；新增对照见下方。搜索或其它调用链的其它临时分配仍未统计。
- **视口输出**：固定 4 行/4 tile，预热后比较每次创建 Vec 与复用 Vec；`buffer_growth_observations` 是调用前后容量增大的次数，**不是全局 allocator 调用数**。记录实际输出容量和 tile 校验值；本场景每次最多四项，复用后容量不再增长。
- **检查点**：状态数为生成参数 / 32；相邻 tile 和间隔 97 的稀疏 tile。比较 `[u8; 256]`、`Box<[u8; 256]>`、`Vec<u8>`，顺序经历填充、clear、分帧 drain、相同位置重新填充。每状态固定 256 字节内容，Box 的已知请求字节/Vec 的实际 capacity 单独累计；两种外置 payload 各创建一次分配，内联数组没有独立分配。每阶段记录 arena、有效状态、payload、访问数与回收量。refill 时间也包含逐状态前驱查询和完整 payload 核验。

`ArenaStats::allocation_calls` 计的是受测 Vec 初次分配/容量增长请求，即使 allocator 原地扩容也记一次，不是系统调用数。`arena_capacity_bytes` 包括未用的 Vec 槽及节点内部 padding；节点内联 `Option<S>` 已含在 arena，不能再加一份内联 payload 字节。外置 payload 只加实际在用的状态，输出 Vec 的外壳容量另列。clear 不析构；drain 返回所有权后，本驱动显式 `out.clear()` 析构，计入 drain 耗时。移出而尚未丢弃的状态仍占内存，不能称为已释放。

这些是明确覆盖的容量和调用计数，**不是进程 RSS、总堆峰值或全局分配剖析**。未包含 allocator 元数据/碎片、源码和其它对象/符号 String/Vec、Update、输入构造、统计结果 Vec、栈帧及其它瞬时分配。arena 在该工作负载不缩容，所以最终容量等于自身峰值；不同生命周期的峰值不能简单相加冒充同时发生的总峰值。用户析构函数不受库的 Budget 时间保证。

## 结果与改进决策

以下解析结果选生成参数 65,536，后三轮非时间指标一致：

| 工作负载 | 实际字节 | 语义节点 | 语义 arena 字节 / 分配调用 | 容器 arena 字节 |
| --- | ---: | ---: | ---: | ---: |
| plain | 65,536 | 11 | 1,152 / 4 | 0 |
| dense | 68,067 | 110,933 | 9,437,184 / 17 | 0 |
| containers | 65,550 | 72,895 | 9,437,184 / 17 | 1,310,912 |

密集语法的主要已测容量来自语义 arena，而不是千字节级查询栈。dense/containers 都落在相同 Vec 容量台阶，不意味着活跃节点数相同。现有 72 字节语义节点仍有较大常数；进一步拆分语义/修订存储值得另做原型，但本实验没有实现拆分或测量其查找成本，不能据此声称一定节省内存或更快。相邻同类节点合并也没有覆盖已发布 ID、局部修改与增量复杂度的完整收益证明，暂不引入。

64 次窗口查询，plain 栈累计 64 次分配/扩容，dense/containers 各 192 次；单次峰值分别 288 / 1,152 / 1,152 字节。全篇查询的峰值为 1,152 / 2,304 / 2,304 字节，增长次数 3 / 4 / 4，没有按文档节点数配置 scratch。初次实验据此识别查询 scratch 复用机会；后续已实现可归还缓冲的借用 API 和 DisplayCursor 自动复用，分配对照见下方，未引入全局缓存、线程局部状态或每查询固定大数组。现有 `viewport_into` 在预热后 64 次查询容量增长为 0，新 Vec 为 64，输出校验值相同，继续使用已有复用接口即可。

**已实施的最小改进**：检查点树的两个 `Option<usize>` 子索引改为 `Option<NonZeroUsize>`（存下标 + 1，与语义树一致），读取减 1。保持 arena 顺序和树形，不进行全树压缩/重建，不改变 API、身份、版本或预算。实际节点非零大小且 Vec 分配上限小于 `isize::MAX`，因此合法节点下标 + 1 不溢出；公开 tile 上限仍由 insert 校验。

下表为 2,048 个状态，arena 包含容量余量；Box/Vec 外部 payload 各另占 524,288 字节：

| 状态/位置 | 节点数 | 节点字节，前 → 后 | arena 字节，前 → 后 | arena 降幅 |
| --- | ---: | ---: | ---: | ---: |
| 内联数组/相邻 | 4,095 | 328 → 312 | 1,343,488 → 1,277,952 | 4.9% |
| Box/相邻 | 4,095 | 72 → 56 | 294,912 → 229,376 | 22.2% |
| Vec/相邻 | 4,095 | 88 → 72 | 360,448 → 294,912 | 18.2% |
| Vec/稀疏 | 17,444 | 88 → 72 | 2,883,584 → 2,359,296 | 18.2% |

压缩前后全部非时间字段中，仅 60 个节点大小/arena 容量值变化，节点数、分配调用、写入访问、查询校验值、回收扫描量及帧数全部相同。因此保留此局部改进；不从单轮耗时声称提速。大型内联状态会被预留在每个内部节点和空槽：本例 Box 后的 arena + payload 为 753,664 字节，内联为 1,277,952 字节，但多出 2,048 次独立 payload 分配。接入方可按状态大小选择 Box，核心不强制装箱；真正的叶 payload 独立 arena/空闲表需要另测索引及回收成本。

**回收收益与边界**：2,048 状态 clear 都只有 1 次根访问，保留全部 payload；drain 后 Box/Vec 各释放 524,288 字节，而内联状态不释放独立堆容量。每帧对象/查询额度各 31，相邻树扫描 4,095 节点、133 帧，稀疏树扫描 17,444 节点、563 帧。两者均移出 2,048 个状态，失效后的逐状态 invalidate 各只访问根一次；当前有效树的移出仍可能需要 O(log T) 更新。输出 Vec 复用、每帧立即丢弃返回值；回收扫描与累计历史节点数有关，不与当前有效状态数成正比。单次预算控制的是扫描节点数，并不把用户析构或整轮扫描变成常数。

回收前后及相同位置 refill 的 arena 容量/分配调用均不变；它回收 payload，**不会归还历史树节点**。固定工作集的反复浏览适合复用现有 arena。历史树容量的显式归还已由下方独立压缩任务实现；本段原 drain 实验本身没有节点回收，也未声称 memory cap。对已释放 payload 的重复回收仍扫描历史节点，调用方应保存 cursor、按需启动新回收轮次。

## 验收边界

7 项独立测试覆盖重复非时间指标、空查询零分配、百万字窗口/全遍历 scratch 对数界、预热视口复用、独立二分区间集合的节点模型、独立插入深度/回收扫描/帧数模型、三种 payload 表示、零预算/非对称预算、部分回收与 BTreeMap 前驱模型、析构计数、旧 token 拒绝及 32 次 clear/refill 容量复用。检查点模型用 1/17/128/2,048 状态、1/97 间隔、1/31/4,096 扫描额度，不以单次机器时间定阈值。已有极值字长索引模型、随机布局和语义回归继续运行。

仅覆盖本机以及实际 i686 的功能/容量模型验证；没有总堆峰值、OOM、其它 ABI、跨机器吞吐或真实终端布局结论。查询 scratch 复用见下方交付；节点本体回收见下方压缩实验；语义/修订拆分与完整内存剖析仍是后续工作。


## 查询 scratch 复用实验

`QueryScratch` 保存已有标注树遍历 Vec。`RunsWithScratch` / `DisplayRunsWithScratch` 临时接管栈并独占借用调用方缓冲，drop 时丢弃未消费帧、归还容量；文本 lifetime 单独绑定 Document。两者仍执行原迭代器，不复制结果或重新解析；`DisplayCursor` 在原预算检查之后使用同一接口，仅跨步骤保留容量。新查询重新建立根帧，不复用旧节点引用、版本、样式或待消费片段。范围/tile 接口、提前退出、追加和释放示例见 [README](../README.md#查询栈复用)。

同一 `storage` 驱动新增每类输入五个阶段：预热语义查询、显示新栈/复用栈、预算游标每步新建/同游标复用。原有压缩/回收阶段和旧基线保留。范围查询仍使用八个中部起点和 256 字节窗口，先各预热一次，再测 64 次；预热分配单列且不计入计时。`display_fresh` 每次构造默认 scratch，同样经过归还接口，比较的是容量复用的影响，不是两版二进制的精确耗时。每次 cursor 请求 256 字节范围，每步预算为 66 bytes / 1 query / 1 object；`cursor_fresh` 每次返回 run 后从当前位置重建游标，以模拟此前每步新栈，`cursor_reused` 保留该窗口内游标，每个新窗口仍重新创建。游标组包含各窗口冷启动分配，没有把它称为全部零分配。

[三轮原始 CSV](query-scratch-baseline.csv) 共 **3,303 条指标、378 个阶段**，每轮非时间字段逐项相同；[环境及源码 SHA-256](query-scratch-environment.txt) 基于 `4248b377f9b7767fc5d66f90b7b14aa7b4adff20` 加本单元工作树，2026-10-30 15:22:40 UTC，ark / x86_64 / Rust 1.99.1。复跑仍使用本文开头的 `scripts/measure-storage.sh`，默认参数不变。记录生成时完整回归也在执行，没有固定 CPU 频率或绑核，因此时间只作原始观察，不据此宣称端到端提速。

生成参数 65,536、每组 64 次窗口的分配结果如下（分配包含扩容请求）：

| 输入 | 语义新栈 → 预热复用 | 显示新栈 → 预热复用 | 窗口预热分配 / 容量字节 | 游标逐步新栈 → 窗口内复用 | 游标峰值容量字节 |
| --- | ---: | ---: | ---: | ---: | ---: |
| plain | 64 → 0 | 64 → 0 | 1 / 288 | 256 → 64 | 288 |
| dense | 192 → 0 | 192 → 0 | 3 / 1,152 | 21,072 → 128 | 576 |
| containers | 192 → 0 | 192 → 0 | 3 / 1,152 | 7,344 → 128 | 576 |

复用前后各组返回数、文本/源码/隐藏样式校验值和峰值容量相同；语义和显示窗口访问数也相同，dense 各 30,128 次，containers 各 20,336 次。游标两路径每组预算字节相同：plain 16,896，dense 706,176，containers 253,192；返回短片段时检查窗口仍完整计费，未通过减少预算扣费掩盖读取。三规模全部执行相同计数验收；原有解析/arena/回收指标与前一实验的压缩后记录相同。

**验收**：新增 11 项测试及 3 项文档样例（含两个 compile-fail 借用约束）。独立字节样式模型覆盖 400 组语法、1,200 个窗口；字面显示期望及所有切点验证实体、Unicode、组合字符、CRLF 和替代映射。复用/原查询逐范围对比全部字段和访问数，覆盖部分 tab、表格、代码/数学块与 tile；空/非法范围、保留返回文本、两个同时查询、跨文档、提前停止及 panic unwind 验证容量归还和借用隔离。流式跨分类窗口的强调/实体/代码/Setext/表格及晚定义在每次追加后重新查询。百万字/千层引用、密集语法与极限 `usize` 树深验证对数栈、窗口访问界和零解析工作；稀疏极值树用写入日志对照，不需要分配巨型文档。

预算测试独立计算 UTF-8 检查窗口和六维费用，覆盖 6 / 7 / 19 / TILE_BYTES + 2 / 10,000 字节额度、共享依赖消费、非对称零额度、Complete、WrongDocument 和 StaleContinuation；拒绝时位置、预算和分配计数均不变。已有显示搜索、摘要/预览、导航与完整分块/预算回归继续验证自动复用的消费者。

容量统计仅覆盖遍历 Vec，不是全局分配器或总内存。预热相同工作集零增长不保证以后更深查询零增长，scratch 保留历史峰值容量直到调用方丢弃。每个活动游标持有自身栈，重建游标或更换调用方 scratch 需重新预热；历史树回收见下方交付；其他未接入消费者的瞬时分配、语义/修订拆分、完整内存峰值和真实终端性能继续保留。


## 检查点历史树压缩实验

此前 drain 实验释放外置 payload 后，2,048 个稀疏 Vec 检查点仍保留 17,444 个节点和 2,359,296 字节 arena。新增 `CheckpointIndex::into_compaction` 显式创建拥有缓存的维护任务：先按有效计数 DFS 跳过整片失效子树，将有效状态及原 token 版本迁到新树；再逐节点弹出旧 arena，将剩余失效 payload 返回调用方。最后一次 pop 后 Vec 长度为零，此时释放旧分配，不用在结束时扫描空状态或调用全树 shrink。新树沿用原身份、serial、文档及 revision，未迁移/已迁移状态的并集供暂停期间查询；没有复制用户状态或重解析源码。接口及示例见 [README](../README.md#检查点历史树压缩)。

每个步骤共享 1 object + 1 query，扣费失败原子不推进。有效叶步骤附带旧树失效和新树插入两次 O(log T) 操作，树访问计数独立记录；普通 DFS/退役步骤 O(1)。N 个历史节点、L 个有效状态的总成本为 O(N + L log T)，scratch 为 O(log T)；未直接按 arena 总量预分配新树。构造只有固定空根和初始栈分配；已有 Vec 扩容是摊销操作，分配器/用户析构没有硬实时上界。新旧两树同时存在，任务期间不能写缓存或应用更新；完成后可继续消费暂存的有序/合并通知，漏通知按既有规则拒绝。直接丢弃任务等同于丢弃缓存；保持任务即可暂停，不会自动在 Drop 中完成压缩。

### 重复测量与结果

沿用本文开头的 `scripts/measure-storage.sh` 和 `crates/mdstream-core/examples/storage.rs`，每个规模新增四种状态/位置各三阶段：填入全部状态并保留每第 16 个、分帧压缩、重填被移出的其余位置。状态数为 128 / 512 / 2,048，稀疏间隔 97、相邻间隔 1，每状态 256 字节，每帧 objects/queries 各 31。clear/drain 的原实验完整保留。压缩计时包含构造、推进、每帧显式丢弃返回状态、有效 token 核验及 finish；refill 包括 payload 与前驱核验，不是裸索引时间。

[三轮原始 CSV](checkpoint-compaction-baseline.csv) 共 **4,563 条指标、486 个阶段**；各轮非时间字段一致，原查询复用基线的 **975 个非时间字段逐项未变**。[环境及源码 SHA-256](checkpoint-compaction-environment.txt) 记录基于 `7e27911e3c078c958c1553e54376974fba895b1c` 加本单元工作树，2026-10-30 15:37:52 UTC，ark / x86_64 / Rust 1.99.1。测量与回归运行有重叠，未固定频率或绑核，时间仅作原始观察，不宣称端到端提速。

2,048 个状态保留 128 个后的本机容量如下：

| 状态/位置 | 节点数，前 → 后 | arena 字节，前 → 后 | arena 降幅 | 已释放外置 payload 字节 |
| --- | ---: | ---: | ---: | ---: |
| 内联数组/相邻 | 4,095 → 767 | 1,277,952 → 319,488 | 75% | 0 |
| Box/相邻 | 4,095 → 767 | 229,376 → 57,344 | 75% | 491,520 |
| Vec/相邻 | 4,095 → 767 | 294,912 → 73,728 | 75% | 491,520 |
| Vec/稀疏 | 17,444 → 1,606 | 2,359,296 → 147,456 | 93.75% | 491,520 |

相邻树遍历 1,279 节点、迁移 128 状态、退役 4,095 节点，合计 5,374 步、174 帧、9,723 次树访问；稀疏树对应 2,104 / 128 / 17,444，合计 19,548 步、631 帧、25,680 次访问。两者 scratch 容量都是 128 字节，4 次分配/增长请求。原 arena 在完成时容量为零，新树保留有效状态，外置有效 payload 另占 32,768 字节；内联状态已计入每节点大小，不能再加一份。

每次 advance 前后可观测的两份 arena 容量之和，Vec 相邻最高 368,640 字节，稀疏最高 2,506,752 字节；**这个观测值不是总堆峰值**，不含 Vec 扩容中分配器可能临时保留的旧内存、输出 Vec、scratch、payload 堆、allocator 元数据或其它文档数据。输出 Vec 的实测容量单列，相邻 Vec 384 字节，稀疏 Vec 96 字节。原 arena 直到最后一个节点退役才归还，不能把每帧 pop 宣称为即时逐页释放。

回填后节点数/arena 容量与原填充相同，有效 token 仍有效；累计分配次数会增加（Vec 相邻 12 → 22 → 24，稀疏 15 → 26 → 30），因此固定位置反复浏览可继续选择原有 drain 复用，历史工作集明显收缩时再显式压缩。完全无效树只需访问根一次，随后 N 次退役；完成后保留一个空根。保留高位稀疏检查点需要对应索引路径，新树仍有 Vec 容量余量，不承诺任何输入压缩后都节省容量。

### 验收与保留边界

新增 **11 项测试**：10 项独立压缩验收与 1 项测量模型。以 BTreeMap 前驱/精确查询、独立 u128 二分区间集合和原 token 为对照，在每次暂停检查查询并集；100 轮随机历史、9,600 次写入/失效/清空操作及 900,000 个完成后查询，32 次不相同位置回填不积累历史节点。惰性父失效、后来单路径恢复、旧 token 与异缓存 token、完全有效树/空树、多轮压缩、分帧 drain 组合、反向插入版本、保留/失效测量 ticket 与漏更新/错误文档均覆盖。新共享测量在 3 种状态数 × 2 种间隔 × 3 种预算下核对节点数、退役量、帧数、容量/有效 payload 和回填校验值。

零/非对称预算、预先消费共享预算、未完成 finish 返回任务及 Covered 重放验证原子暂停。4,096 个稀疏非 Clone 状态验证库内零用户析构、独立返回值所有权、旧 arena 最终释放；分别在两个阶段丢弃任务验证每个剩余状态恰好析构一次。极值索引包括 `isize::MAX - 1`，每步树访问和任务 scratch 有字长界，宽整数区间模型避免依赖被测算术；x86_64 与实际 i686 的 debug/release 完整回归继续验证既有布局、语义、流式和预算契约。README 另有完整调用样例及所有权编译失败测试。

此接口是显式、独占写入的维护任务，不能在暂停时 apply/insert，也不支持撤销已经开始的压缩而立即取回可写缓存。保留任务可恢复；需要缓存写入时先完成任务，或由宿主明确丢弃并重建。并发可写协议、硬内存上限、渐进释放旧 Vec 分配、总堆/OOM、序号耗尽和其它 ABI 仍未交付；没有改动核心语法或扩展终端 UI。
